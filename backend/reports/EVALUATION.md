# Passage model: evaluation

Backtest of the inside-Parliament passage model (MODEL_SPEC §7). Generated by
`uv run python -m westminster_weather.model.cli evaluate`; numbers are in `metrics.json`.

## How it was tested

- **Trained on** bills introduced in sessions 20-30
  (2006-07 to 2017-19), using only data available on 2019-10-14.
- **Tested on** 222 bills introduced in sessions 34-39
  (2019 onwards) that have finished; the current session is not scored.
- Each test bill was forecast on the day it entered each stage, as if it were that day:
  1,281 forecasts, 1,207 of them for bills that became law.

## Results

| | Model | B1 | B0 |
|---|---|---|---|
| Average error in Royal Assent date (days) | **73** | 83 | 107 |

- **The model beats both baselines on timing.** B1 uses the typical remaining time
  from the current stage; B0 the typical total time from 1st reading.
- **Errors fall as a bill progresses** (table below): this is what live updating is for.
- **Uncertainty windows are too narrow:** the 80% window contained the real Royal Assent date
  52% of the time (target 80%). Most misses are bills that
  took longer than forecast.
- **The chance of becoming law is too pessimistic:** forecasts averaged
  80% but 94% became law.
  The Brier score (0.1036) is worse than always forecasting the
  overall pass rate (0.0544).
- **Ranking is good:** concordance index 0.772 (0.5 = random, 1 = perfect)
  for which bills get Royal Assent sooner.

## What drives speed

Largest shared effects in the advance hazard (effect on the daily chance of moving on):

| Factor | Effect | |
|---|---|---|
| 2nd and 3rd reading on the same day | 3.17× | faster |
| Northern Ireland Office | 2.77× | faster |
| HM Treasury | 1.80× | faster |
| Started in the Lords | 0.65× | slower |
| Carried over from previous session | 0.68× | slower |
| 0-5 sitting days left in session | 1.42× | faster |
| More stage sittings so far (+1 SD) | 0.78× | slower |
| Department for Business and Trade | 0.85× | slower |

The end of a session speeds bills up; carried-over and Lords-first bills are slower.

## Limitations

- **Session-end risk is overstated.** The model treats the end of a session as an outside event,
  so a bill that is behind schedule often "dies" in the simulation. In reality governments time
  prorogation around their main bills, so few bills die at a session end. This is the main cause
  of the low pass probabilities and too-early dates.
- **Sessions since 2019 have been longer and bills slower** than in the training period, which the
  model, trained on 2006-2019, does not anticipate.
- **Future carry-over motions are not anticipated**: a bill introduced late in a session is
  forecast as if it must finish before the session ends (e.g. Online Safety Bill).
- **No vote, rebellion or Lords-defeat data yet** (BUILD_PLAN task 7 skipped): defeat risk is a
  fixed 0.2% per Commons vote stage.
- **Committee of the whole House** is only recorded separately by the Bills API from 2022-23,
  so the model cannot learn its effect.
- **Small sample** (about 590 bills, 66 failures): wide intervals are honest, not a bug.
- Pre-Parliament stages and commencement are not covered.
